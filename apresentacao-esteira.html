Como o grupo trabalha

Do commit ao deploy

O caminho que o CD já descreve

  1. 01

    Pull request

    CI, Gitleaks, Trivy, SBOM e CodeQL. O client ganha URL de preview na Vercel.

  2. 02

    Merge na main

    Um build: vercel build --prod. A API vira imagem com os 12 primeiros caracteres do SHA.

  3. 03

    Imagem no GHCR

    Trivy na imagem. Se passar, o push publica ghcr.io/.../server-api.

  4. 04

    Homologação

    vercel deploy --prebuilt --prod --skip-domain. O domínio público não se move. O smoke procura <app-root.

  5. 05

    DAST

    ZAP baseline na URL de homologação, com as regras de .zap/rules.tsv.

  6. 06

    Tag v*

    vercel promote aponta o domínio para esse deployment. Health check falho chama vercel rollback.

A API para no passo 03. A imagem fica versionada no registry. Ainda não há host para colocá-la no ar.

Ambientes e promoção

O artefato testado é o que recebe o domínio

Ambiente Quem cria O que já acontece
Local docker compose e ng serve Desenvolvimento, com o seed da imobiliária Relax Inn
Preview Job preview, no PR URL efêmera. O environment do GitHub se chama preview
Homologação Job staging, no push da main Deployment imutável, sem domínio. Smoke obrigatório. Alias opcional em STAGING_ALIAS
Produção Job promote-production, na tag Environment production. Procura o deployment daquele SHA e promove. Exige PRODUCTION_URL

Build único

O merge constrói. A tag não constrói de novo. vercel promote só move o domínio para o deployment que já passou pelo smoke.

A Vercel não publica sozinha

Em vercel.json, github.enabled está false. O deploy sai do workflow, depois dos passos anteriores do job.

cd.yml · os cinco jobs

Preview, imagem, homologação, ZAP, tag

preview

URL por pull request

vercel pull no environment preview, vercel build e vercel deploy --prebuilt. A URL volta no environment do GitHub.

package-api

Imagem com scan e SBOM

Build local, Trivy, CycloneDX, depois push para o GHCR com a tag do SHA e edge na main.

staging

Deploy sem domínio

--skip-domain cria o deployment de produção sem apontar o site. O smoke exige <app-root na resposta.

dast-staging

ZAP nessa URL

Depende do staging. fail_action: true. Se houver segredo de bypass da Vercel, o ZAP passa pela proteção do deployment.

promote-production

A tag só promove

Procura o deployment READY daquele commit. vercel promote move o domínio. Se o health check falha, vercel rollback devolve o ponteiro anterior.

Segredos que o CD já lê

Três obrigatórios

VERCEL_TOKEN, VERCEL_ORG_ID e VERCEL_PROJECT_ID. PRODUCTION_URL é variável. Sem ela, a tag falha antes de promover.
